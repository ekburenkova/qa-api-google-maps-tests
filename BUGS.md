### BUG-01. Некорректный статус-код при создании локации с пустым полем name

**Связанный тест-кейс:** Tест-кейс №2. Создание локации с пустым полем name
**Приоритет:** Средний  
**Severity:** Major

**Шаги для воспроизведения:**

1. Отправить POST запрос на `/maps/api/place/add/json`
2. Передать пустое значение в поле `name`

**Ожидаемый результат:**

- Статус-код: 400  
- В ответе присутствует поле `msg` с описанием ошибки

**Фактический результат:**

- Статус-код: 200  
- JSON-ответ пустой

**Комментарий:** API принимает некорректные данные и возвращает успешный статус, что нарушает контракт API.


### BUG-02. Некорректный статус-код при создании локации без поля location

**Комментарий:** Отсутствие обязательного поля не валидируется API.

### BUG-04. Несоответствие структуры ответа GET документации (latitude/longitude вместо lat/lng)

**Связанный тест-кейс:** Tест-кейс №4. Получение существующей локации
**Приоритет:** Средний  
**Severity:** Minor

**Шаги для воспроизведения:**

1. Создать локацию через POST  
2. Отправить GET запрос на `/maps/api/place/get/json` с валидным `place_id`

**Ожидаемый результат:**

- В ответе поле `location` содержит:
  - `lat`
  - `lng`

(в соответствии с документацией)

**Фактический результат:**

- В ответе возвращаются:
  - `latitude`
  - `longitude`
- Значения представлены в виде строк

**Комментарий:** Структура ответа не соответствует документации API, что может привести к ошибкам при интеграции.
