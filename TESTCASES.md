# Тест-кейсы

### Tест-кейс №1. Создание локации с валидными данными

Метод: POST  
Ресурс: /maps/api/place/add/json  
Тип: Позитивный  
Приоритет: Высокий

Шаги:

1. Отправить POST запрос с валидными данными

Ожидаемый результат:

Ожидаемый результат:

* Статус-код: 200
* В ответе присутствуют поля: status, place_id, scope, reference, id
* Поле `status` = "OK"
* Поле `place_id` присутствует и не пустое
* `place_id` соответствует формату UUID

### Tест-кейс №4. Получение существующей локации

Метод: GET  
Ресурс: /maps/api/place/get/json  
Тип: Корнер-кейс (идемпотентность)
Приоритет: Высокий

Шаги:

1. Отправить POST запрос для создания объявления с валидными данными
2. Отправить GET запрос с существующим place_id

Ожидаемый результат:

* Статус-код: 200
* В ответе присутствуют поля: location, accuracy, name, phone_number, address, types, website, language
* Поля не пустые
* Значения полей `name`, `address` соответствуют переданным
* Значения координат `lat`/`lng` в `location` соответствуют переданным

### Tест-кейс №6. Обновление адреса валидными данными

Метод: PUT  
Ресурс: /maps/api/place/update/json  
Тип: Позитивный
Приоритет: Высокий

Шаги:

1. Отправить POST запрос с валидными данными
2. Отправить запрос PUT, в поле address передать строку
3. Отправить запрос GET для получение информации по локации

Ожидаемый результат:

Для PUT:
* Статус-код: 200
* В ответе присутствует поле `msg`
* Поле `msg` = "Address successfully updated"

Для GET:
* Статус-код: 200
* Поле `address` содержит новое значение

### Tест-кейс №11. Полный цикл (flow): создание, изменение, удаление

Метод: POST, PUT, DELETE, GET

Ресурсы: 
/maps/api/place/add/json
/maps/api/place/get/json
/maps/api/place/update/json
/maps/api/place/delete/json

Тип: Позитивный

Шаги:

1. Отправить POST с валидными данными
2. Отправить запрос GET на получение информации с валидным place_id
3. Отправить запрос PUT и в поле address ввести новый валидный адрес
4. Отправить запрос GET на получение информации с валидным place_id
5. Отправить запрос DELETE с валидным place_id
6. Отправить запрос GET на получение информации с валидным place_id

Ожидаемый результат:

**Шаг 1 (POST):**
- Статус-код: 200
- Поле `status` = "OK"
- Присутствует `place_id`
- `place_id` соответствует формату UUID
- Все обязательные поля присутствуют и не пустые

**Шаг 2 (GET до обновления):**
- Статус-код: 200
- Данные соответствуют отправленным при создании
- Поля присутствуют и не пустые

**Шаг 3 (PUT):**
- Статус-код: 200
- Поле `msg` = "Address successfully updated"

**Шаг 4 (GET после обновления):**
- Статус-код: 200
- Поле `address` содержит новое значение

**Шаг 5 (DELETE):**
- Статус-код: 200
- Поле `status` = "OK"

**Шаг 6 (GET после удаления):**
- Статус-код: 404
- Поле `msg` содержит "failed"
